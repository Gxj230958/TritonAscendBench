### Reference math (oracle helper)

Grouped MoE expert GEMM with token-id scatter (the fused_moe_kernel
output domain). For each padded block of `block_size` sorted slots,
the block's expert `e = expert_ids[blk]` matmuls the gathered token
rows by that expert's weight and (optionally) scales by the token's
routing weight; the result for slot `s` is scattered to
`out[sorted_token_ids[s]]` -- exactly what the kernel does via
`C[offs_token]`. a: [n_tokens, K]; b: [n_experts, N, K];
out: [n_tokens, N] (top_k == 1, so the output is indexed directly by
token id). Slots holding the padding sentinel (`token id >= n_tokens`)
write nothing; their rows -- and rows of tokens no slot routes -- stay
zero. Partial routing (fewer aligned slots E*4 than tokens B, e.g.
shape H1) is in scope: unrouted token rows are legitimately zero.
