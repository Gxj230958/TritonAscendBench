## P2 — Operator-clean extraction (root fix; v2 adds the anchor + slicer hardening)

**P2.0 — Pre-slice anchor (else S2 becomes self-equivalence).** analysis S2
severs FROM the committed kernel.py and compares AGAINST that same file
(`phase_a_prime.py:2382,2448,2469,2517`); launcher tasks also exec `_pa_launcher.py` into the
loaded kernel module (`_pa_subproc_runner.py:591`, `_pa_oracle_check_runner.py:325`). So slicing
the committed file makes S2 verify sliced-severed == sliced-original = meaningless. **The
anchor MUST be a byte snapshot of the PRE-SLICE committed `kernel.py` PLUS its launcher sidecar
semantics — NOT the upstream source** (L2_35 shows meta `upstream` path/hash differ from the
committed kernel.py header, and the real graded path is `_pa_launcher.py::run`; upstream source may
only be an EXTRA check, and only usable if byte-identical to the snapshot). Slice-equivalence gate:
run the TRUE graded path (entrypoint + launcher sidecar) on identical inputs from BOTH the sliced
kernel.py and the pre-slice snapshot; require BIT-EXACT output. Only then are the sliced file's S2
(severs cleanly) + C2 (aligns oracle) meaningful.

**P2.1 — Harden the slicer, then make it the freezer.** Extend
`_slice_to_entrypoint_closure` to handle the decline cases review listed: global constants, aliases,
decorators, imported helper symbols, dynamic launcher dispatch, and no-top-level-import tasks;
widen the closure walk + allow-set safely (keep fail-closed). Resolve the 20 ambiguous
`kernel.py::run + launcher` tasks (use the launcher's launched-jit roots as the true graded set).
Invoke at freeze/slice time for the manifest tasks (P2.3 reachability predicate). **Fail-closed**: any task the hardened
slicer still can't prove-safe (residual vllm import, unresolved roots, slice-equiv fail) → keep
whole-file, mark `phase_a_prime.unsliceable=<reason>`, count honestly. No forced unsafe slicing.

**P2.2 — Per-task gated verify+rollout.** For each task: slice → P2.0 slice-equiv gate → S2 → C2,
all GREEN → replace kernel.py + re-stamp `standalone_sha256`; else revert to whole-file + log. Run
behind a `--slice` flag; sliced + whole-file in parallel for one release before switchover.

**P2.3 — Scope .** The scope predicate is NOT
text-based launch detection (that's wrong: L3_01 has a real grid launch of `reduce_segments` at
`kernel.py:743` that a naive `name[grid](...)` regex with `[^\]]*` misses on nested-bracket grids).
The correct predicate is **graded-path reachability**: a task is in scope iff the file contains
launched JIT kernels NOT reachable from the TRUE graded path (entrypoint + launcher closure). Those
unreachable launches are the droppable siblings P2 removes; if every launch IS reachable from the
graded path (e.g. L3_01 if its 2D graded path genuinely needs both `kernel_unified_attention` and
`reduce_segments`), the task is a legitimate multi-launch operator and is EXCLUDED. P2 ships
`scripts/multi_launched_manifest.py` that reuses the SAME graded-path closure walk as the slicer and
emits the scope list from code (rollout scope = the manifest, never a hand-typed number; L3_01's
membership is decided by the reachability analysis, not by hand). Tasks whose every launch is
graded-path-reachable, and single-jit tasks → leave.
