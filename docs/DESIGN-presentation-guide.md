# TritonAscendBench — 对外交流讲解指南

> 本文是 `docs/DESIGN-V2.md` 的陪同讲解材料,用于与外部专家做方案对齐。规范体本身保持零讲解性元叙述;讲法、提问预案与边界声明集中在此。

## 1. 30 秒电梯陈述

> 已在 vLLM / SGLang 生产推理路径运行的 GPU Triton 算子,迁移到昇腾 910B 的 `triton-ascend` 后端后,是否还能保持被冻结的上游真实语义,并在 910B 上达到可解释、可复现的性能?

这是一个 **GPU Triton → NPU Triton 迁移基准**(不是生成基准)。双目标:迁移**是否正确**(复现被可复现冻结的上游 kernel 行为)、迁移**是否高效**(按 910B Roofline 理论上限归一化比效率)。**正确性是排名资格门,性能是入门后的排名指标。**

## 2. 推荐讲解顺序

按问题展开,避免一上来抛术语。每步对应 `DESIGN-V2.md` 的章节锚点。

| # | 讲什么 | 关键句 | 锚点 |
|---|--------|--------|------|
| 1 | **先讲问题** | 这是迁移基准,不是"由算法描述生成新 kernel" | §1.1–1.2 |
| 2 | **再讲真值** | 真值不是手写 PyTorch 公式,而是被冻结的上游生产 kernel 行为 | §1.3 |
| 3 | **冻结为什么难** | 只 vendor 文件不够——live import 让行为随环境漂移,只是快照不是冻结 | §4.1 |
| 4 | **冻结如何可信** | severing 切断依赖;等价校验在 GPU 上严格 bit-exact 证明行为没变(CPU 只预检不判 PASS) | §4.2 |
| 5 | **入口如何不选错** | 入口双锚:≥2 shape oracle 一致 + CPU 等价预检,过了才写 meta | §4.3 |
| 6 | **评测如何防作弊** | candidate 看不到 oracle/golden,三进程隔离,静态检查 + canary + 计时仲裁 | §6、§8 |
| 7 | **性能为什么这样算** | 不用 GPU 延迟做分母;用 910B Roofline 理论延迟,衡量"达到 910B 自身上限的几成" | §9 |
| 8 | **发布门与固定分母** | 失败/BLOCKED 任务不能从分母消失;少做难题不抬分 | §4.4、§9 |

## 3. 三句话收束

讲完把所有细节收束为专家需要判断的三件事:

1. **真值是否可信** —— 冻结 + 等价与确定性校验 + 入口双锚。
2. **候选是否真正完成迁移** —— 隔离 + 静态防御 + canary + fallback 归一为 correctness fail。
3. **性能分是否可复现且不可被选择性操纵** —— 910B Roofline 固定分母 + 不剔分母 + 发布门。

## 4. 预期质疑与应答

专家最可能问的硬问题与可辩护应答:

| 质疑 | 应答要点 |
|------|----------|
| 为什么不用 GPU 延迟做性能分母? | GPU/NPU 峰值算力、带宽、调度不同,绝对延迟跨硬件不可比。用 910B 自身 Roofline 理论下界,分数是"达到 910B 自身上限的比例",硬件代差在分母推导中被构造性消去。 |
| oracle 不就又成了独立真值源? | 不是。oracle 经入口双锚对齐到冻结上游语义,只用于评测期生成 golden;真值始终是被冻结的上游 kernel,不是 PyTorch 公式。 |
| cost model 自己算错怎么办? | 每题 `meta.yaml.cost_model` 解析 $W/M$ 必须与插桩 GPU-Triton 参考实测交叉校验;偏差超容差 ⇒ cost-model BLOCKED,进发布门,不以错误基线产分。这是性能侧的"双锚"。 |
| 困难题冻结失败就被悄悄拿掉? | 不能。发布门:任一 score-eligible 任务未达 `release_status=PASS` ⇒ 整套不可发布;固定分母 $|S|$,失败/BLOCKED/fallback 计 0 或 ε,**绝不剔分母**。 |
| 正确但慢的实现能蒙混? | 不能。`fallback_detected` 在评分前归一为 correctness fail,过不了资格门;性能再按 Roofline 效率排名。 |
| 100 题代表性够吗? | 100 题全部取自 vLLM/SGLang 现网生产推理路径,覆盖 attention/MoE/SSM/量化/sampling/LoRA 等功能族(见 `kernel-select.md`),非合成算子。 |
| 为什么没有 FBGEMM / 题号有跳号? | 选型原则是"只收 vLLM/SGLang 生产路径";原唯一的 FBGEMM 题(jagged attention)非该路径,已删以保持选型自洽,变长 attention 由在途 vLLM/SGLang 算子覆盖。 |
| 这套已经实现了吗? | **如实说**:`DESIGN-V2.md` 是目标设计规范。可复现冻结链(severing/等价校验/确定性/双锚/双哈希)与发布门骨架已实现;双目标 Roofline 的 cost-model 交叉校验与复合 `release_status` 是已定决策、属后续实现阶段。冻结/正确性侧与代码一致,性能 Roofline 侧代码在追平。 |

## 5. 配套材料与边界声明

带这几份,边界主动说清,别等专家"抓":

- **`DESIGN-V2.md`** —— 设计规范(目标态,present tense)。讲解主材料。
- **`kernel-select.md`** —— 100 题选型方案(规模/分布/原则/排除/完整清单),回答"为什么是这些题"。
- **入库流程图** —— 有两版:**目标设计版**(含 cost-model 步与复合发布门)用于讲方案;**当前实现版**(发布门仅 `phase_a_prime.status`、代码内部仍用 S2/S3 命名、无 cost-model 步)反映此刻代码。讲方案用前者,被追问实现进度时如实给后者,不混用。
- **核心边界一句话**:本基准是 **provider-only**——维护方维护题库/引擎/榜单,不写 NPU kernel、不做 PyTorch→Triton 生成、不做 GPU↔NPU 绝对延迟竞速。

> 守则:设计可以是目标态,但被问"实现了吗"时必须如实区分"已实现 / 已定但待实现",不 overclaim——这是与专家建立信任的前提。
